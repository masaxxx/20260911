# x-parody-script — Xの時事ネタ ×「裏の物語」ブラックコメディ脚本

参照ファイル（各 Step で指定した章だけを読む。付録と background.md は読まなくてよい）:
- [references/trend-sourcing.md](references/trend-sourcing.md) — 収集（Tier 0〜4）、除外ゲート、検索レシピ S1〜S8、裏取り・鮮度、記録・候補リスト形式
- [references/guardrails.md](references/guardrails.md) — トリアージ（Q1〜Q10 → RED / YELLOW / GREEN）、実名の扱い、ディスクレーマー予算、断り方、チェックリスト
- [references/comedy-craft.md](references/comedy-craft.md) — キャスト、「裏の物語」の発想法、毒の調整、台本テンプレート、ルーブリック
- [references/background.md](references/background.md) — 法令・判例・作風分析・出典（根拠を確かめたいときだけ）

## NEVER（参照ファイルを読まなくても必ず守る）

1. **RED は書かない・調べない・残さない。** 実在人物の性的なうわさ／「流出動画・画像」／ディープフェイク（真偽も、否定や「デマを笑う」目的かも問わない）、事件・事故・災害・自殺の被害者や遺族、未成年、私人・一般人の炎上、実在の人物・企業の未確認のネガティブな疑惑、判決確定前の刑事事件、属性（人種・国籍・民族・宗教・障害・性別・性的指向など）を笑うネタ、進行中の災害・戦争・テロ、実在の人物・団体への暴力や脅迫のオチ。判定した時点で検索・要約・記録をやめる。名前を伏せる、「噂として」、似た架空人物に置き換える、といった抜け道も使わない。
2. RED の話題の人名・キーワードを、検索クエリ・ファイル名・ログ・台本・タイトル・タグ・返答に書かない。除外ログは**コード×件数だけ**（`RED: R1×1, R4×2`）。例外なし。一般化した一行説明も書かない。
3. 元作品（Family Guy／Stewie）の作品名・キャラ名・外見・決め台詞・声真似・「天才赤ん坊」という器を、台本・タイトル・サムネイル・概要欄・タグに使わない。借りるのはトーンと技法だけ。
4. 実在人物の発言を捏造して本物らしく見せない。実在人物の顔や声の合成（ディープフェイク・ボイスクローン）、本物そっくりのニュース画面やX投稿画面を作らない。
5. 黒幕に実在の人物・企業・団体を据えない。「ありそうな不祥事」（不正・不倫・薬物・病気・品質の偽装）を捏造しない。一目でウソと分かる荒唐無稽さにする。
6. 裏取りできていない話を事実として書かない。実在の固有名詞は、ホオンの事実行・境界テロップの媒体名・概要欄と、guardrails.md §5.4 の条件を満たすタイトル・タグにだけ置き、裏の物語には置かない。実在の企業・人物の言葉として『』で引くのは、出典で一字一句確認できた語だけ。

## Step 0 前提を決める

- **基準日**: `TZ=Asia/Tokyo date '+%F %H:%M'` で JST の日付を取り、ファイル名・鮮度・検索の「今日・昨日・一昨日」に使う。依頼文の日付と違えば依頼文を優先し、メタ情報に両方書く。
- **依頼の型**: 話題の指定 → Tier 0（trend-sourcing.md §2-1）／カテゴリ・期間だけ（「今週の政治か値上げ」）→ §2-2／指定なし → X のトレンドから自動で選ぶ。
- **フォーマット**: `--long`（既定。本編5〜8分）／`--shorts`（60秒）。
- **ダークネス**: `--dark=N`（既定3）。ショートは最大3に丸めて報告し、3の中で濃度を最大にする（comedy-craft.md §4-3）。どのレベルでも NEVER と §4-4 のハードラインは変わらない。
- **キャスト**: 既定はモンステラ公爵（ボケ）／ホオン（事実担当のツッコミ）／モブ田（代役・被害者）（comedy-craft.md §2）。別キャラの指定には従う。ただし NEVER 3 の範囲内で、「事実担当」と「代役」の機能は残す。
- **出力先**: 呼び出し側が指定したらそこ。なければプロジェクトルートの `parody-scripts/`（以下 `<出力先>`）。
- **実行モード**: 対話（ユーザーと会話中）か、非対話（サブエージェント実行や「おまかせ」）か。

## Step 1 候補を集める（trend-sourcing.md §0〜§2・§4〜§5。§3 は `X_BEARER_TOKEN` があるときだけ）

- Tier 1（X API。トークンの値は表示しない）→ Tier 2（アグリゲータへの WebFetch。1回だけ）→ Tier 3（WebSearch レシピ S1〜S8）→ Tier 4（対話時のみ）。クラウドでは Tier 3 が主力。
- 見出しを読んだ時点で除外ゲート（R コード）を当てる。当たったものにはそれ以上触れない。
- 検索予算は20〜25回。証拠の強さは「本文 ＞ リンク（Links のタイトル＋URL）＞ 要約一致」（§5-1）。出来事の核は本文かリンクで確かめる。

## Step 2 全候補をトリアージする（guardrails.md §1〜§2、trend-sourcing.md §7〜§9）

- 残った候補すべてに Q1〜Q10 を当て、RED / YELLOW（Y1〜Y7）/ GREEN（G1〜G7）を付ける。迷ったら1段重くする。
- 未確認の話題: 実在の人物・企業の**ネガティブな**内容なら R5（コードだけ）。ネガティブでなければ「落選（未確認）」に名前と理由を書いてよい。
- **依頼された話題が RED**: 調べない。返答の先頭1文で断り、理由を一言だけ添える（人名・キーワードは繰り返さない）。対話モード → guardrails.md §6.3／§6.4 の角度2〜3案か当日の候補を出して選んでもらう。非対話モード → 代替案は出さず、当日のトレンドで Step 1 から書き切る（§6.3 の「うわさ産業」の角度は使わない）。ログには `R1×1（依頼）` と数える。
- 候補リスト（trend-sourcing.md §9 の形式。選べる候補5件以上が目標、届かなくても予算を使い切ったら進む）を `<出力先>/candidates/YYYY-MM-DD-candidates.md` に保存する。

## Step 3 採点して1件を選ぶ

- **選べる候補** = 裏取りが確認済／条件付き、かつ鮮度が新鮮／継続（Tier 0 とユーザーが言った期間の中は例外）。
- **点数** = 笑いの伸びしろ（1〜5）＋ 鮮度（新鮮5・継続4）＋ 安全（GREEN 5、YELLOW 4、被害を受けた人が近い YELLOW 3）。条件付きは −1。同点なら安全の高いほう。Y コードの種類だけで差を付けない。
- 上位3件を1行ピッチ（裏の物語の角度＋公爵の立ち位置＋笑いの源泉）付きで示す。対話モード: ユーザーに選んでもらう（「おまかせ」なら1位）。非対話モード: 1位を採用して止まらずに続ける。
- 選べる候補が0件: 対話モードなら Tier 4 で聞く。非対話モードなら G7（公爵の自分いじり回）か、裏取りした季節ネタ（G2）で書き、その旨を報告する。

## Step 4 事実シートを作る（trend-sourcing.md §7、guardrails.md §4.2）

- 何が起きたか（誰が・何を・いつ・数字と単位）を、独立したソース2件以上で確認する（A/B を1件以上。公式発表そのものが出来事なら A 1件。実在の人物・企業のネガティブな出来事なら A/B を2件以上）。転載は元媒体が分かるものだけ数える。URL はこの回のツール出力に出たものだけ。
- 「確認できた事実」「【要約一致】（報道では、と添えて使う。公開前に照合）」「確認できなかった情報（台本では使わない）」に分ける。
- 企業・人物の言葉を『』で引くのは、A の文言か、B の見出しに引用符付きで出た語だけ。それ以外は要旨で言い、オチのフリ（嘲笑の的）にしない。
- 【トリアージ結果】ブロック（guardrails.md §1 STEP 5）をここで書く（毎回、台本より前に）。
- **笑いの源泉**を1行で書く: 人々はこの話題の何のギャップに笑ったか。現実側がすでに出した最強のボケ（パロディ広告・公式の言い回しなど、A/B で確認できるもの）は何か。

## Step 5 「裏の物語」を発想し、1つに決める（comedy-craft.md §0・§2・§3・§4）

- 捨て大喜利3本 → 「本当の理由は……」を**15〜20本**（10の型のうち8つ以上。§3-3 の実例の骨格の言い換えは数えない）→ 採点（意外性・内的論理・刃・絵・伸びしろ・身内化）→ 安全のふるい（§3-1 と §4-4 だけ）→ 上位案を合体して1つにする。
- **ルール・主張・公爵の私的動機**をそれぞれ1文で決め、はしご①〜⑤＋落下（第一候補は皮肉な成功）、カットアウェイ候補3〜5本、ボタン（ルールが公爵自身に跳ね返る形）を先に決める。
- フック・はしご⑤・崩壊の一言・ボタンは3案ずつ書いてから選ぶ。グレーなら §4-5 の順で処理し、それでもグレーなら次点の候補に戻る。

## Step 6 台本を書く（comedy-craft.md §5）

- 本編は §5-3、ショートは §5-2 のテンプレートで書く。★には強さとメカニクス番号を付ける（§5-1 の較正）。
- **免責表示は guardrails.md §5 の「ディスクレーマー予算」だけ**（これで全部。台本に注意書きを足さない）:
  1. 冒頭0〜5秒の画面下にフィクション表示、全編の隅に「PARODY／フィクション」の透かし
  2. ホオンの事実行の直後に境界テロップを1回（元媒体・日付）
  3. 音声ディスクレーマー1回（4秒以内・ボケで終える・毎回新作・コールドオープンには置かない）
  4. モブ田が実在の役職を演じるときだけ、役ごとに1回「※この〇〇はモブ田です」
  5. エンドカード「※すべてフィクションです。元ネタの事実は概要欄の出典をご確認ください。」
- 構造の安全: 黒幕は架空（公爵本人、架空の組織、擬人化したモノ）。実在の固有名詞は事実行だけ。X の画面は架空の UI と架空アカウント＋PARODY の透かし。
- 事実ゾーン（本編20秒・ショート8秒以内）では、公爵は事実を変えない反応だけ挟んでよい。境界テロップの後10秒以内に、源泉のギャップへの公爵の反応で★★以上。

## Step 7 パンチアップ（comedy-craft.md §6）

- 冷たい読み合わせ（★を外して読み直し、付け直す）→ ルーブリック13項目 → 3案出し → 弱点トップ3 → 直す。字数・★間隔・例文との一致は**数える**（`python3` 可）。
- 優先順位: 安全と権利（第12項目）＞ 弱いボケを捨てる ＞ 密度。捨てて密度が割れたら、ルールから出た新しいボケを書く。事実ゾーンは密度の計算から外す。
- 第12項目が不合格なら、その場面ごと差し替える。

## Step 8 最終確認（guardrails.md §5・§7）

- §7-A（台本段階）の12項目をすべて「はい」にする。1つでも「いいえ」なら直すか、ネタを捨てて Step 3 に戻る。§7-B（公開前TODO）は書き出すだけでよい。
- 概要欄テキスト（§5.1。元ネタ行と出典を埋め、AI の行は使う／使わないを確定させる）と、タイトル／サムネ案（§5.4。前提は事実シートどおり、実名は条件付き）を用意する。

## Step 9 保存して報告する

保存先は `<出力先>/YYYY-MM-DD-<ascii-slug>.md`。slug は英小文字・数字・ハイフンだけで、人名は入れない。同名のファイルがあれば末尾に `-2` などを付ける。

```markdown
- 元ネタ: <トピック>（判定: GREEN / YELLOW＋コード）・基準日: JST YYYY-MM-DD
- 出典: [B] 媒体（元媒体） | 日付 | タイトル | URL（概要欄の出典と同じ集合）
- 鮮度 ・ フォーマット ・ ダークネス ・ キャスト ・ 候補リスト: candidates/YYYY-MM-DD-candidates.md

## 脚本本文（★〔M番号〕付き）
## セルフレビュー

```

返信は短く: 保存パス、選んだトピックと判定、裏の物語の一行ピッチ、尺とダークネス、除外ログ（RED はコード×件数だけ）、公開前TODO の要点。実在の人物・企業の**ネガティブな出来事**を扱う回（Y1、Y2 の不祥事・炎上、Y4）では、収益化の前に専門家（弁護士）へ確認するよう一言添える。
