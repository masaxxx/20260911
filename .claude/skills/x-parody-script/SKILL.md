# x-parody-script — Xの時事ネタ ×「裏の物語」ブラックコメディ脚本

参照ファイル（各 Step で指定した章を Read する）:
- [references/trend-sourcing.md](references/trend-sourcing.md) — トレンド収集（Tier 0〜4）、除外ゲート A〜H、検索レシピ S1〜S8、裏取り、候補リスト形式
- [references/guardrails.md](references/guardrails.md) — トリアージ（Q1〜Q10 → RED / YELLOW / GREEN）、法務・規約、ディスクレーマー、断り方
- [references/comedy-craft.md](references/comedy-craft.md) — 笑いの技法、既定キャスト、「裏の物語」の発想法、台本テンプレート、ルーブリック

## NEVER（参照ファイルを読まなくても必ず守る）

1. **RED は書かない・調べない・残さない。** 実在人物の性的なうわさ／「流出動画・画像」／ディープフェイク（真偽も、否定や「デマを笑う」目的かも問わない）、事件・事故・災害・自殺の被害者や遺族、未成年、私人・一般人の炎上、実在の人物・企業の未確認の疑惑、判決確定前の刑事事件、属性（人種・国籍・民族・宗教・障害・性別・性的指向など）を笑うネタ、進行中の災害・戦争・テロ、実在の人物・団体への暴力や脅迫のオチ。判定した時点で検索・要約・記録をやめる。名前を伏せる、「噂として」、似た架空人物に置き換える、といった抜け道も使わない。
2. RED の話題の人名・キーワードを、検索クエリ・ファイル名・ログ・台本・タイトル・タグに書かない。除外ログは**コード×件数だけ**。
3. 元作品（Family Guy／Stewie）の作品名・キャラ名・外見・決め台詞・声真似・「天才赤ん坊」という器を、台本・タイトル・サムネイル・概要欄・タグに使わない。借りるのはトーンと技法だけ。
4. 実在人物の発言を捏造して本物らしく見せない。実在人物の顔や声の合成（ディープフェイク・ボイスクローン）、本物そっくりのニュース画面やX投稿画面を作らない。
5. 黒幕に実在の人物・企業・団体を据えない。「ありそうな不祥事」（不正・不倫・薬物・病気・品質の偽装）を捏造しない。一目でウソと分かる荒唐無稽さにする。
6. 裏取りできていない話を事実として書かない。実在の固有名詞はホオンの「事実の一行」と概要欄の出典にだけ置く。

## Step 0 引数を解釈する

- **トピック**: 指定があれば Tier 0（trend-sourcing.md §2）で扱う。なければ X のトレンドから自動で選ぶ。
- **フォーマット**: `--long`（既定。本編5〜8分）／`--shorts`（60秒）。
- **ダークネス**: `--dark=N`（既定3）。ショートは最大3に丸め、丸めたことを報告する。どのレベルでも NEVER と comedy-craft.md §4-4 のハードラインは変わらない。
- **キャスト**: 既定はモンステラ公爵（ボケ・ナレーター）／ホオン（事実担当のツッコミ）／モブ田（代役・被害者）（comedy-craft.md §2）。ユーザーが別キャラを指定したら従う。ただし NEVER 3 の範囲内で、「事実担当」と「代役」の機能は残す。
- **実行モード**: 対話（ユーザーと会話中）か、非対話（サブエージェント実行や「おまかせ」）か。

## Step 1 候補を集める（trend-sourcing.md §0〜§6）

- Tier 1（X API。`X_BEARER_TOKEN` があるとき。値は表示しない）→ Tier 2（アグリゲータへの WebFetch。1回だけ試す）→ Tier 3（WebSearch レシピ S1〜S8）→ Tier 4（対話時のみ、ユーザーに聞く）。クラウド環境では Tier 3 が主力になる。
- 見出しを読んだ時点で除外ゲート A〜H を当てる。当たったものにはそれ以上触れない。
- 検索予算は20〜25回。証拠は Links に出たタイトルと URL だけ。日付は URL・タイトル・Unix 秒で確認する（毎年ある行事の「去年の記事」に注意）。

## Step 2 全候補をトリアージする（guardrails.md §1〜§2）

- 残った候補すべてに Q1〜Q10 を当て、RED / YELLOW（Y1〜Y7）/ GREEN（G1〜G7）を付ける。迷ったら1段重くする。
- RED は候補表から黙って外し、ログには `RED: R1×1, R4×2` のようにコード×件数だけを残す。
- **ユーザーが指定したトピックが RED のとき**: 1〜2文で断り、理由を一言だけ添える（「本人への実害とうわさの拡散になるため」など）。続けて guardrails.md §6.3／§6.4 の安全な角度を2〜3案、または当日の GREEN／YELLOW の候補を出す。抜け道の言い分には §6.5 の短い返答を返す。説教はしない。
- 候補リスト（10〜15件。trend-sourcing.md §9 の形式）を `parody-scripts/candidates/YYYY-MM-DD-candidates.md` に保存する。

## Step 3 上位3件に絞り、1件を選ぶ

- 選べる候補（確認済／条件付き）を「笑いの伸びしろ × 鮮度 × 安全（GREEN > YELLOW）」で採点し、上位3件を1行ピッチ（裏の物語の角度＋公爵の立ち位置）付きで示す。
- 対話モード: 3件を見せてユーザーに選んでもらう（「おまかせ」なら1位）。非対話モード: 1位を採用し、止まらずに続ける。
- 選べる候補が0件: 対話モードなら Tier 4 で聞く。非対話モードなら G7（公爵の自分いじり回）か、裏取りした季節ネタ（G2）で書き、その旨を報告する。

## Step 4 事実シートを作る

- 何が起きたか（誰が・何を・いつ・数字）を、独立したソース2件以上（A/B を1件以上含む。実在の人物・企業のネガティブな出来事が核なら A/B を2件以上）で確認する。媒体・日付・URL を記録する（URL はツールの出力に出たものだけ）。
- 「確認できた事実」と「確認できなかった情報（台本では使わない）」を分ける。未確認の数値や発言は台本に入れない。
- guardrails.md §1 STEP 5 の【トリアージ結果】ブロックをここで書く（毎回、台本より前に）。

## Step 5 「裏の物語」を発想し、1つに決める（comedy-craft.md §3）

- 「本当の理由は……」を**15本以上**、発想の10の型から幅広く出す → 採点表（意外性・内的論理・絵になる・伸びしろ・身内化）→ 安全のふるい（§3-1 の四つの鉄則、§4-4）→ 上位案を合体して1つにする。
- 「この回のルール」を1文で決め、はしご①〜⑤＋落下、カットアウェイ候補3〜5本、ボタン（オチ）を先に決める。
- グレーだと感じたら §4-5 の順で処理し、それでもグレーならネタごと捨てて次点の候補に戻る。

## Step 6 台本を書く（comedy-craft.md §5）

- 本編は §5-3、ショートは §5-2 のテンプレートで書く。★で狙っている笑いの強さを付ける。
- 必須の安全装置:
  1. 冒頭0〜5秒の画面下にフィクション表示、全編の隅に「PARODY／フィクション」の透かし
  2. ホオンの事実行の直後に「※ここまで実際の報道（媒体・日付）／ここから先はフィクション」
  3. 実在の固有名詞は事実行だけ。裏の物語では役職名・架空名にする
  4. 黒幕は架空（公爵本人、架空の組織、擬人化したモノのいずれか）
  5. 実在人物の役はモブ田が演じ、テロップで明示する
  6. X の画面は架空の UI と架空アカウント＋PARODY の透かし
  7. エンドカードに「※すべてフィクションです。元ネタの事実は概要欄の出典をご確認ください。」

## Step 7 パンチアップ（comedy-craft.md §6）

- 10項目のルーブリックで自己採点する → ★を A/B/C で評価して弱い30%を削る → 密度（本編は15秒、ショートは7秒に★1つ以上）、具体性、文末オチ、コールバック、カットアウェイの本数を直す。
- 第9項目（安全と権利）が不合格なら、その場面ごと差し替える。

## Step 8 最終ガードレール確認（guardrails.md §5・§7）

- §7 のチェックリスト12項目をすべて「はい」にする。1つでも「いいえ」なら直すか、ネタを捨てて Step 3 に戻る。
- 概要欄テキスト（§5.1 をほぼそのまま使い、出典を入れる）、音声のディスクレーマー（§5.3 をキャラの口調で）、タイトルかサムネイルに「パロディ／妄想／もしも／ウソ裏話」のいずれか（§5.4）を用意する。
