# x-parody-script — Xの時事ネタ ×「裏の物語」ブラックコメディ脚本

ゴールは**笑える台本**。安全はネタ選びと架空化で取り、架空の世界の中では遠慮しない。

参照（各 Step が指す章だけ読む）:
- [references/trend-sourcing.md](references/trend-sourcing.md) — 収集、除外ゲート、検索レシピ、裏取り、候補リスト
- [references/guardrails.md](references/guardrails.md) — RED／YELLOW／GREEN、実名、ディスクレーマー、チェックリスト
- [references/comedy-craft.md](references/comedy-craft.md) — キャスト、発想法、ダークネス、テンプレート、失敗ギャラリー
- [references/background.md](references/background.md) — 根拠・作風分析・実測ログ（参考。読まなくてよい）

## NEVER（参照を読めなくても守る）

1. **RED は書かない・調べない・残さない**（guardrails.md §1 の R1〜R10: 実在人物の性的なうわさ・流出・ディープフェイク／被害者・遺族／未成年／私人／実在の人物・企業の未確認のネガティブ情報／属性ネタ／判決確定前の刑事事件／本物に見える偽物／進行中の惨事／実在への暴力オチ）。判定した時点で手を止める。伏せ字・「噂として」・否定目的・似た架空人物といった抜け道も使わない。
2. RED の人名・キーワードは、クエリ・ファイル名・ログ・台本・タイトル・タグ・返答のどこにも書かない。ログはコード×件数だけ。実在の人物・企業にとってネガティブになりうる落選話題も、コードだけで記録する（理由欄にも中身を書かない。trend-sourcing.md §7-3）。
3. 元作品（Family Guy／Stewie）の名前・作品名・外見・決め台詞・声真似・「天才赤ん坊」の器を使わない。借りるのはトーンと技法だけ。
4. 実在人物の発言を捏造して本物らしく見せない。顔・声の合成、本物そっくりのニュース画面・X投稿画面を作らない。
5. 黒幕は架空にする。「ありそうな不祥事」を捏造しない。一目でウソと分かる荒唐無稽さにする。
6. 裏取りできていない話を事実として書かない。実在の人物・団体・企業・商品・サービスの名前は、事実行・境界テロップ・概要欄・タイトル／タグ（guardrails.md §3・§5）にだけ置く（地名・名所・一般的な機能名は対象外）。実在の人物・企業の言葉として『』で引くのは、出典で一字一句確認できた語だけ（架空の台詞は自由）。

## Step 0 前提
- **基準日**: `TZ=Asia/Tokyo date '+%F %H:%M'`。依頼文の日付と違えば依頼文を優先し、両方をメタ情報に書く。
- **依頼の型**: 話題の指定 → trend-sourcing.md §2／カテゴリ・期間だけ → 同 §2 後半／指定なし → Xトレンドから自動で選ぶ。
- **フォーマット**: `--long`（既定。本編は約5分。6〜8分は材料が稼いだときだけ）／`--shorts`（60秒）。
- **ダークネス**: `--dark=N`（1〜5、既定3）。本編・ショートとも4〜5を使ってよい。条件は、闇の向き先が架空のキャスト・抽象概念・公爵自身だけであること（comedy-craft.md §4）。ハードラインはどのレベルでも同じ。
- **キャスト**: 既定はモンステラ公爵・ホオン・モブ田（comedy-craft.md §1）。別キャラの指定には従うが、NEVER 3 を守り、「事実担当」と「代役」の機能は残す。
- **出力先**: 指定があればそこ。なければ `parody-scripts/`（以下 `<出力先>`）。
- **モード**: 対話（ユーザーと会話中）／非対話（サブエージェント・「おまかせ」）。

## Step 1 候補を集める（trend-sourcing.md §0〜§5）
- Tier 1（トークンがあれば）→ Tier 2（WebFetch は1回だけ）→ Tier 3（WebSearch S1〜S8。クラウドでの主力）→ Tier 4（対話時のみ）。
- 見出しを読んだ時点で除外ゲート。検索予算20〜25回で、選べる候補6〜12件が目標。

## Step 2 トリアージ（guardrails.md §1〜§2、trend-sourcing.md §6〜§7）
- 全候補に R1〜R10 を当て、残りを YELLOW（Y1〜Y7）／GREEN（G1〜G7）に分ける。迷ったら1段重く。
- **依頼された話題が RED**: 調べない。返答の先頭1文で断り、理由を一言だけ添える（人名・キーワードは繰り返さない）。対話 → guardrails.md §6 の代替案か当日の候補。非対話 → 代替案は出さず、当日のトレンドで Step 1 から書き切る。ログは `R1×1（依頼）`。
- 候補リストを `<出力先>/candidates/YYYY-MM-DD-candidates.md` に保存する（形式と落選ログは trend-sourcing.md §7）。

## Step 3 1件を選ぶ
- 選べる候補 = 確認済（要約ベースを含む）または条件付き、かつ新鮮／継続（Tier 0 と指定期間の中は例外）。
- 点数 = 笑いの伸びしろ（1〜5）＋鮮度（新鮮5・継続4）＋安全（GREEN 5／YELLOW 4／被害を受けた人が近い YELLOW 3）。条件付き・要約ベースは −1。同点なら安全が高いほう。Y コードの種類だけで差を付けない。
- 上位3件を1行ピッチで示す。対話: 選んでもらう（おまかせなら1位）。非対話: 1位で続ける。
- 0件: 対話なら Tier 4。非対話なら G7（公爵の自分いじり回）か、裏取りした季節ネタ（G2）で書き、その旨を報告する。

## Step 4 事実シート（trend-sourcing.md §6、guardrails.md §3）
- 誰が・何を・いつ・数字（単位つき）を確かめる。GREEN・中立の話題は信頼できる A/B 1件、実在の人物・企業のネガティブな出来事は独立した A/B 2件。WebFetch 不可の環境では「確認済（要約ベース）」の条件で確認し、台本では「〜と報じられています」と書いて公開前TODOに入れる。URL はこの回のツール出力に出たものだけ。
- 「確認できた事実」「要約ベース・【要約一致】（報道では、と添える）」「使わない未確認情報」に分ける。
- 【トリアージ結果】ブロック（guardrails.md §1 STEP 5）を書く。
- **笑いの源泉**を1行: 人々は何のギャップに笑ったか。**現実がすでに出した最強のボケ**（公式の言い回し、他社のパロディ広告など。A/B で確認できるもの、またはバズの中身として言える C＝trend-sourcing.md §6-1）を名指しする。

## Step 5 裏の物語を決める（comedy-craft.md §1〜§4）
- `parody-scripts/`（または `<出力先>`）の既存台本を grep し、直近で使った装置（ボタン・ダークターン・カットアウェイの仕掛け）を避ける（例: `grep -h "^- 装置" parody-scripts/*.md`。本文も見る）。comedy-craft.md §6 の焼き畑リストも避ける。
- 源泉 →「本当の理由は……」20本（ありがちな3本は書いて捨てる）→ 1つ選ぶ → ルール・主張・動機を1文ずつ → 形を変えながら登るはしご → 皮肉な成功＋二の矢 → ボタン（ルールを極端まで押して跳ね返す）。
- フック・はしご⑤・崩壊・ボタンは3案ずつ書いてから選ぶ。グレーなら comedy-craft.md §4 の順で処理し、それでもグレーなら次点の候補に戻る。

## Step 6 書く（comedy-craft.md §5）
- ショートは §5-2、本編は §5-3。★／★★／★★★は声が出る行にだけ付ける。
- 免責表示は guardrails.md §4 の固定セットだけ（足さない・削らない）。
- 事実ゾーン（本編20秒・ショート8秒以内）でも、公爵は事実を変えない反応で笑いを取ってよい。
- その回の決め語は、本編6回・ショート3回まで。

## Step 7 パンチアップ（別の目）
- Agent ツールが使えるなら x-parody-punchup サブエージェントに台本パスを渡してパンチアップさせる（使えなければ同じ手順を自分で、台本を一度閉じて冷読してから行う）。手順は [x-parody-punchup](../../agents/x-parody-punchup.md)。
- 戻ってきたら、事実行・出典・ディスクレーマー・実名の置き場所が変わっていないことを確かめる。

## Step 8 最終確認（guardrails.md §4・§5・§7）
- §7-A をすべて「はい」にする。1つでも「いいえ」なら直すか、ネタを捨てて Step 3 に戻る。§7-B は書き出すだけ。
- 概要欄テキスト（§4）と、タイトル／サムネ案（§5）を用意する。

## Step 9 保存・報告
保存先は `<出力先>/YYYY-MM-DD-<ascii-slug>.md`（英小文字・数字・ハイフンだけ。人名は入れない。同名があれば `-2`）。

```markdown
# <タイトル案1>
## メタ情報
- 元ネタ: <トピック>（GREEN / YELLOW＋コード）・基準日: JST YYYY-MM-DD
- 出典: [B] 媒体（元媒体） | 日付 | タイトル | URL（概要欄の出典と同じ）
- 形式 ・ ダークネス ・ キャスト ・ 候補リスト: candidates/YYYY-MM-DD-candidates.md
- 装置: ボタン=<一言>／ダークターン=<一言>／カットアウェイ=<一言ずつ>／決め語=<語>
## トリアージ結果
## 事実シート（確認できた事実／要約ベース・【要約一致】／使わない未確認情報／笑いの源泉と現実の最強のボケ）
## 裏の物語（ルール・主張・動機、はしご、崩壊と二の矢、ボタン、捨てた上位案3つ）
## 脚本本文
## セルフレビュー（comedy-craft.md §7。現実の最強ボケと、それを超える1行の引用／パンチアップの変更ログ／§7-A）
## 公開前TODO（§7-B）
## 概要欄用テキスト
## タイトル／サムネ案（3案）
```

返信は短く: 保存パス、トピックと判定、裏の物語の一行ピッチ、尺とダークネス、除外ログ（RED はコード×件数だけ）、公開前TODO の要点。実在の人物・企業のネガティブな出来事を扱う回（Y1、Y2 の不祥事・炎上、Y4）では、収益化の前に専門家（弁護士）への確認を勧める。
